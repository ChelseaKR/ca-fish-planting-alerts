# Snapshot contract (v1)

The pipeline publishes **one static JSON file** that the app GETs. This
directory is the contract; the pipeline owns it, the app consumes it.

## Where to GET it

| What | URL |
|---|---|
| Snapshot (this contract) | `https://chelseakr.github.io/ca-fish-planting-alerts/snapshot/v1.json` |
| Schema it validates against | `https://chelseakr.github.io/ca-fish-planting-alerts/schema/snapshot.v1.json` (same bytes as `schema/snapshot.v1.json` in this repo) |

The domain is undecided (DECISIONS 0006). When a custom domain is set, the
`github.io` URL becomes a 301 to it, so **follow redirects**. The path
`/snapshot/v1.json` is stable for the life of v1; a breaking change ships as
`/snapshot/v2.json` alongside, never in place.

- Served with `Content-Type: application/json` from GitHub Pages (which sets
  `ETag`/`Last-Modified`; send `If-None-Match` on refresh — a 304 costs
  nothing).
- Regenerated by a scheduled run **once a day**; the source changes weekly.
  A failed or stale run publishes nothing, so the file is either the last good
  snapshot or a newer good one — never a partial one.
- Size on 2026-09-13: one year of CDFW's rolling window is ~2,000 plants
  across ~385 waters; expect **~400–600 KB uncompressed**, gzip ~60–90 KB,
  growing by roughly that much per year of history.

## Reading it

- `schema/snapshot.v1.json` is JSON Schema 2020-12 and is the source of
  truth. Everything below is commentary.
- **A plant is a week, not a day.** `week` is `{start, end, label}` where
  `start` is a Sunday, `end` is the following Saturday, and `label` is
  `week of YYYY-MM-DD`. CDFW says: "More specific dates are not given to avoid
  focusing excess fishing activity immediately after a plant." Never render a
  plant as a single date; never say "planted on".
- **Never say "stocked".** CDFW: "all fish plants are subject to change
  depending on road, water, weather and operational conditions." Say
  "scheduled" / "listed for the week of …".
- `source_week` is the week containing the date the CDFW page itself said was
  "today" when fetched. "This week" in the app should mean `source_week`, not
  the device's clock — they differ only when the snapshot is old, and then the
  honest thing is to show the snapshot's own week.
- `this_week[]` is a convenience index of `{water_id, species}` for
  `source_week`; it is derived from `waters[].plants` and tested to agree.
  **It can legitimately be empty** (a fresh page with no plants this week).
  It is never produced from a stale or failed fetch, because no snapshot is
  built then.
- Future weeks exist: CDFW lists about two weeks ahead. A plant with
  `week.start > source_week.start` is scheduled, not current. The app's alert
  ("a favourite appears in the new week") should fire when a
  `(water_id, week, species)` with `status == "listed"` appears in a refreshed
  snapshot that was not in the previous one, for any week
  `>= source_week` — that is the diff the app owns.
- `status`: `listed` or `removed`. `removed` means CDFW listed the plant and
  later dropped it while the week was still inside the page's window
  ("subject to change"). History is append-only: a plant never disappears from
  a later snapshot, it flips to `removed`.
- `waters[].id` is `cdfw-<StockingWaterID>` — CDFW's own numeric key, taken
  from the map link on every schedule row. It is stable because it is theirs.
  Names are not keys: on 2026-09-13 five published names ("Silver Lake",
  "Bass Lake", "Deer Creek", "Sacramento River", "Blue Lake Upper") each map
  to two or three different ids.
- `waters[].slug` is the site path segment (`/water/<slug>/`); assigned once
  in the alias table, never changed even if CDFW respells the water.
- `waters[].location` is `null` unless it came from a licensed source named in
  `location.source`. Coordinates are never guessed.
- `waters[].last_listed_week` is the newest listed week that is not in the
  future — "last planted week of …" for the water page.
- Dates are America/Los_Angeles civil dates; timestamps are UTC `Z`.

## Versioning

`schema_version` is a constant `1`. Additive, optional fields may be added to
v1 without notice (readers must ignore unknown fields — note the schema is
`additionalProperties: false` for the pipeline's own validation, which is
stricter than what a reader should enforce). Anything else is v2 at a new URL.
